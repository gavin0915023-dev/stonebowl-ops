# 石小满 · 接单出餐工作台

面向石锅拌饭门店的单店经营软件，重点覆盖接单、厨房制作、待取餐和交接。提供明确隔离的演示空间与手工导入空间。本软件尚未连接美团开放平台，不会接收真实平台推送，也不会向美团回写状态。

## 已实现的核心流程

订单状态按以下顺序流转：

```text
待接单 new → 制作中 preparing → 待取餐 ready → 已交接 handed_over
      └→ 已取消 cancelled ←┘
```

待接单和制作中的订单可填写原因后取消；已出餐的待取餐订单只能确认交接。已交接、已取消均为终态。禁止跳级或回退，状态变化记录在订单历史中。这里的“已交接”是门店记录，不代表美团配送完成、结算完成或退款完成。

- 订单列表、状态筛选、搜索、订单详情及状态操作。
- 厨房看板、菜品数量和规格、顾客备注、预计出餐及超时提示。
- 演示订单生成，用于熟悉操作；规范 JSON 订单导入，用于迁移或手工录入。
- 依据 Asia/Shanghai 自然日统计订单与营业金额；金额使用整数分存储。
- 数据存入 Cloudflare D1，本地开发使用项目内的 SQLite 持久化目录。

演示空间使用 `mode: "demo"`；手工导入空间使用 `mode: "live"`。两者分别查询、导入和操作，演示数据不混入另一空间的统计。`live` 只是数据空间名称，不表示美团已接入。

## 技术栈与目录

- React 19、TypeScript、Vinext/Vite：界面和服务端接口。
- Cloudflare Workers、D1、Drizzle ORM：运行环境、SQLite 数据与迁移。
- ChatGPT 登录：按当前登录用户隔离数据；本地便携开发提供 loopback 模拟登录。
- Node.js 原生 `node:test`：不依赖外部服务的领域规则测试。

```text
app/             界面、登录辅助与 API
lib/domain.ts    订单状态、输入校验、金额及上海日期纯函数
db/              数据库访问与 Drizzle schema
drizzle/         版本化 SQL 迁移
tests/           领域规则自动测试
.openai/         Sites 托管声明
scripts/         开发、构建和运行辅助脚本
```

## 本地启动（Windows PowerShell）

建议使用 Node.js 24，以直接执行 TypeScript 领域测试。项目运行基线为 Node.js >=22.13.0。

1. 在本项目目录安装锁定依赖；已有可用 `node_modules` 时无需重复安装：

   ```powershell
   npm ci
   ```

   Sites 工作流也可使用 `npm run install:ci`。仅在确实要调整依赖时使用 `npm install` 并检查锁文件变更，不要同时运行多个安装进程。

2. 首次使用数据库前构建，生成本地 Wrangler 配置：

   ```powershell
   npm run build
   ```

3. 查看 `drizzle/` 中的 SQL 迁移，按文件顺序逐个执行尚未应用的迁移。将下例中的文件名替换成项目中实际的迁移文件：

   ```powershell
   Get-ChildItem drizzle/*.sql
   node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/<待执行的迁移文件.sql>
   ```

   不要再次执行已经应用的 SQL。迁移需要先构建出的 `dist/server/wrangler.json`。`.wrangler/state` 是本地数据库持久化根目录，无需额外加 `v3`。本地迁移只影响本地数据库，正式发布的迁移由托管发布流程处理。

4. 启动开发服务：

   ```powershell
   npm run dev
   ```

   默认访问 `http://127.0.0.1:5173`，实际地址以终端输出为准。需要其他端口时使用 `npm run dev -- --port 5174`。

5. 在同一浏览器访问以下地址完成本地模拟登录，然后进入工作台：

   ```text
   http://127.0.0.1:5173/signin-with-chatgpt?return_to=/
   ```

   便携开发模式的模拟用户为 `local_seedy`（`seedy@sites.test`）。仅 loopback 开发请求提供该模拟登录；正式构建不包含模拟登录。正式托管使用平台提供的 ChatGPT 登录。

只有修改 `db/schema.ts` 后才需要 `npm run db:generate` 生成新迁移，并检查生成 SQL。首次运行已有项目时，不应为了“初始化”重复生成同样迁移。

## JSON 导入规范

以下是本软件定义的中间格式，**不是美团原生订单 JSON、导出文件或官方 API 格式**。如果你已有美团导出数据，需要先将相应字段转换为此格式。直接上传未经转换的美团原始文件不保证可识别。

```json
{
  "mode": "live",
  "orders": [
    {
      "externalId": "MT-20261105-0001",
      "channel": "meituan-import",
      "customerName": "演示顾客",
      "deliveryType": "delivery",
      "note": "少辣，不放香菜",
      "prepMinutes": 15,
      "items": [
        {
          "name": "牛肉石锅拌饭",
          "spec": "标准份",
          "quantity": 1,
          "unitPriceCents": 2590
        }
      ]
    }
  ]
}
```

- 每个导入批次最多 100 单；导入前校验批次内容，错误数据不会静默替换成可用值。
- `externalId` 是来源系统稳定且唯一的订单号。批量导入的每笔订单均需提供该字段；单笔手工创建可不填。重复外部单号由数据库防重处理，不会生成第二份同一订单。
- `channel` 支持 `manual` 和 `meituan-import`。`meituan-import` 仅表示数据来源标签，不代表平台授权或同步。
- 每单包含 1–40 项菜品；`items[].quantity` 为 1–99 的整数。`unitPriceCents` 是整数分，例如 25.90 元写为 `2590`，不要传 `25.9`、货币符号或价格字符串。
- `prepMinutes` 为 3–120 的整数，是从本软件接收订单时起的预计制作分钟数。服务端生成新订单的创建时间、出餐截止时间和初始状态。
- 不要传入 `status`、`createdAt`、`dueAt` 试图覆盖服务端状态或时间。因此导入适合当前待接订单，不是历史订单及平台配送状态的还原工具。
- 取消只改变本软件内的记录；顾客退款、平台取消和骑手协调仍需在现有美团商家工具中完成。

在实际使用前，先在演示空间导入同样结构的小批量样例核对菜名、规格、数量和金额。切换手工导入空间后再处理需要留存的订单。

## 导出与备份

工作台中的导出功能用于留存当前订单数据。导出的 JSON 可供检查和备份，不保证与“新订单导入”结构完全相同；尤其已经出餐、取消、历史时间和事件记录不能靠新订单导入还原。

本地完整数据库位于忽略提交的 `.wrangler/state`。需要完整本地备份时，先停止本地服务，再复制整个 `.wrangler/state` 目录至单独的备份位置，并保留对应源码和迁移版本。导出文件可能包含顾客信息，应存放在受控位置。

```powershell
npx tsc --noEmit

```

领域测试覆盖合法与非法状态流转、取消原因、终态保护、整数分金额、数量和输入校验、导入批次限制、demo/live 模式校验，以及上海日期边界和闰年规则。数据库防重、并发控制、身份隔离和页面交互需要配合接口及浏览器验收，不能仅靠纯函数测试证明。

构建完成后可使用 `npm start` 在 loopback 预览生成的 Worker，默认共享 `.wrangler/state`。它不会发布网站，也不模拟登录；日常开发与本地模拟登录请使用 `npm run dev`。

## 使用范围与后续接入

当前版本是按登录用户隔离的单店工作台，尚未实现多位员工共享同一门店、员工角色权限、班次和交接班管理。不同 ChatGPT 用户看到的数据不自动共享；请勿将其当成已经完成员工协作的生产接单系统。

订单列表和统计按所选上海自然日查询，默认查看当天；厨房看板独立显示全部日期尚未完成的订单，避免午夜后遗漏仍在制作或等待交接的订单。订单列表会提示其他日期的待办。所选日期和跨日待办各最多返回 2000 单，超限时界面提示截断；相应统计和导出不能当作全量数据，应先完善服务端分页再用于高单量门店。

公开托管页面允许访客使用自己的 ChatGPT 账号登录，各账号数据独立；公开访问不意味着可以匿名查看其他人的订单。首次登录可手动载入演示订单。Docker 容器的公开入口仅开放虚构演示空间，不开放真实营业数据。构建与导出方式见 `DEPLOY.md`；源代码包和 Dockerfile 本身不等于已构建的容器镜像。

已完成 TypeScript 检查、生产构建、19 项领域与网关测试，以及真实生产 Worker/D1 的 8 项 HTTP 集成检查；另验证了本地 D1 迁移的重复启动与已执行 SQL 改动拒绝。浏览器控制服务当前不可用，因此尚未完成视觉与交互的浏览器验收。线上平台已确认成功部署并设为公开访问，当前环境自动请求线上网址被 Cloudflare 安全策略拦截，不能据此保证所有网络下的浏览器可访问性。

美团实时接单需另行完成合规的平台授权、商家及门店映射、回调验证、幂等接收、状态查询与平台能力核实。本项目未配置美团密钥、未实现平台回调、不会轮询真实订单或回写美团。预计出餐时间、取消和交接均为本软件内的操作记录。

本地端口只监听 loopback，适合同机验收。需要跨设备厨房使用或正式运营时，应先完成托管发布、门店协作权限和真实接单渠道接入；不要把本地模拟登录服务直接暴露到公网。
