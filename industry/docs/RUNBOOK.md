> 本手册是**可执行流程模板**。带 `【待填】` 的项必须由真实团队补齐，不得留空上线。

- [ ] CI 全绿：单元测试、集成测试、构建、契约校验、依赖漏洞扫描
- [ ] 并发压测报告已归档，无超卖 / 重复扣 / 负库存
- [ ] 备份已生成且**完成一次恢复演练**，结果写入 `DRILL-RECORD.md`
- [ ] 所有必需 secrets 已在部署平台配置：`DB_PASSWORD`、`TICKET_SECRET`（≥32 字节）、`STAFF_KEY`、`ALLOWED_ORIGIN`
- [ ] `demo-payments=false`，`StartupGuard` 已验证会拒绝弱配置启动
- [ ] Flyway 迁移在预发环境执行通过，`ddl-auto=validate`
- [ ] 监控告警接收人【待填】、值班表【待填】、故障升级路径【待填】
- [ ] 回滚目标版本与镜像摘要已记录

## 2. 部署步骤

1. 冻结变更，通知相关方。
2. 备份数据库并**验证备份可读**（见 `scripts/backup-restore.mjs`）。
3. 预发执行迁移，跑冒烟用例（下单 → 支付 → 核销 / 状态流全链路）。
4. 灰度：先小比例流量，观察错误率、P99 延迟、库存差值、订单状态分布。
5. 全量；观察窗口不少于【待填】分钟。
6. 记录版本、镜像摘要、迁移版本、操作人。

## 3. 回滚

**原则：只回滚应用，不回滚已应用的数据库迁移。** 迁移必须向后兼容（只加列不加约束、分阶段删除字段）。

1. 停止新版本流量，切回上一版本镜像。
2. 若新版本已写入不兼容数据，按预先演练的数据修复脚本处理，**禁止直接删表或改迁移历史**。
3. 核对订单总数、库存 `reserved` 与订单状态一致性。
4. 复盘并更新 ADR。

## 4. 故障场景

| 现象 | 首判 | 处置 |
|---|---|---|
| 下单 5xx 激增 | DB 连接池 / 锁等待 | 查 `/actuator/health`、慢 SQL、锁等待；必要时限流，不重启掩盖现场 |
| 余票显示异常 | Go 缓存脏读或上游超时 | 展示层降级隐藏余票；**下单仍走主库**，不得用缓存修复 |
| 核销全部失败 | Rust 验签服务或密钥不一致 | fail-closed 保持拒绝；核对 `TICKET_SECRET` 各服务一致；禁止临时放行 |
| 迁移校验失败、循环重启 | 有人修改了已应用迁移 | 保持上一版本；恢复兼容镜像或按 ADR-003 追加新迁移 |
| 待支付订单堆积 | 定时释放任务未执行 | 检查调度与 `@Scheduled` 线程；手工触发前先备份 |
| 订餐写接口 403 | Origin / 会话校验 | 确认 `PUBLIC_ORIGIN` 与实际访问来源精确一致，勿关闭校验 |

## 5. 备份与恢复

- 频率【待填】，保留期【待填】，异地副本【待填】。
- 订票：PostgreSQL → `pg_dump -Fc`；恢复用 `pg_restore`，恢复后必须跑一致性校验（订单数、`reserved` 汇总、孤立记录）。
- 订餐：D1 本地 SQLite 快照位于 `.wrangler/state`；单副本约束下先停写再快照，恢复后校验迁移登记表。
- **备份有效性以恢复演练为准**，只生成文件不算完成。

## 6. 可观测基线

每条日志须含 `traceId`；至少监控：请求错误率、P99 延迟、下单成功率、库存剩余与预占差值、待支付超时量、验签失败率、迁移状态、容器健康。告警阈值【待填】。

## 7. 明确不做

不自动放行核销、不绕过迁移校验、不用缓存判定库存、不在生产开启 demo 支付、不把弱密钥写进任何可启动配置。
