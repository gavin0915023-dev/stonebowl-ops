# 需求规格与验收标准

版本 1.0 · 适用于「汴京十二时订票」与「石小满接单出餐工作台」

## 1. 范围

本规格描述**工程系统能力**，不含对外营业资质、真实资金流、景区出票与第三方平台对接（见根目录 README 的 P0 边界）。

## 2. 功能需求

### 订票

| ID | 需求 | 验收标准 |
|---|---|---|
| FR-T1 | 查询票种与余票 | `GET /api/tickets`、`GET /api/availability` 返回确定结构；非法日期与票种返回 400 |
| FR-T2 | 创建订单 | 服务端计算金额，客户端传入价格一律忽略；数量 1–10；手机号存储前脱敏 |
| FR-T3 | 幂等下单 | 相同 `X-Device-Id` + `Idempotency-Key` 重复提交返回同一订单，库存只扣一次 |
| FR-T4 | 库存不超卖 | N 个并发请求竞争最后 1 份库存，成功数恰好为 1，其余返回明确错误 |
| FR-T5 | 超时释放 | 待支付订单 15 分钟后自动释放库存，重复释放不产生负库存 |
| FR-T6 | 模拟支付与电子票 | 演示模式下生成签名票；生产模式必须接入真实支付后方可出票（当前范围外） |
| FR-T7 | 验签与单次核销 | 篡改 token、非当日、超数量一律拒绝；同一票第二次核销返回 409 |
| FR-T8 | 三维园区与降级 | WebGL 可用时展示园区；不可用时自动切换可点击平面图 |

### 订餐

| ID | 需求 | 验收标准 |
|---|---|---|
| FR-S1 | 订单状态流 | `new → preparing → ready → handed_over`，禁止跳级与回退 |
| FR-S2 | 取消 | 仅 `new`/`preparing` 可取消，必须填写 1–200 字原因 |
| FR-S3 | 金额与时间 | 金额以整数分存储；统计按 Asia/Shanghai 自然日 |
| FR-S4 | 演示数据隔离 | `demo` 与 `live` 空间分别查询统计，演示数据不混入营业空间 |
| FR-S5 | 幂等导入 | 同一 `channel` + `externalId` 重复导入不覆盖已有状态 |
| FR-S6 | 迁移完整性 | 已执行迁移被编辑/删除/重排时拒绝启动 |

## 3. 非功能需求

| ID | 类别 | 要求 | 验证方式 |
|---|---|---|---|
| NFR-1 | 配置安全 | 生产环境缺任一必需变量即拒绝启动；不得存在可用弱默认密钥 | `StartupGuard` + `verify.mjs` 扫描 |
| NFR-2 | 可观测 | 每个请求带 `X-Trace-Id` 并进入日志；暴露 health/metrics | 过滤器 + Actuator |
| NFR-3 | 一致性 | 并发下不超卖、不重复扣、不产生负库存 | `loadtest/order-race.mjs` |
| NFR-4 | 可恢复 | 备份可被还原且通过校验；演练有记录 | `scripts/backup-restore.mjs` |
| NFR-5 | 可回滚 | 发布失败可在既定步骤内回退到上一版本 | `RUNBOOK.md` |
| NFR-6 | 契约 | 所有 HTTP 接口在 OpenAPI 中有定义且与实际一致 | CI 契约校验 |
| NFR-7 | 变更管理 | 数据库结构变更只能经版本化迁移；禁止运行时自动改表 | Flyway `validate` / 迁移哈希 |

## 4. 明确的范围外（Out of Scope）

真实支付与退款、真实景区出票与闸机核销、微信公众号登录与实名、美团开放平台推送与状态回传、发票与结算、面向公众的合规备案。这些需要经营主体、平台授权与法务流程，**不得以实现"模拟接口"冒充完成**。

## 5. 验收门槛

发布到生产前，以下必须全部有真实记录（非模板）：并发压测报告、恢复演练记录、契约校验结果、依赖漏洞扫描结果、回滚演练结果。缺任一项不进入发布流程。
